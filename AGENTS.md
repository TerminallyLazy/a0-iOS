# Agent Zero iOS

## Purpose
Native companion for an existing Agent Zero server. The approved design is in docs/PLAN.md.

## Ownership
- Sources/A0Core owns protocol DTOs, HTTP authentication, sync reduction, per-chat drafts/delivery reconciliation, actor-backed protected session/profile storage, credential-store interfaces, transient QR import validation/review state, bounded snapshot retry policy, staged realtime recovery, authenticated project/model-preset operations, server context accounting, the nonisolated speech-permission bridge, and transport contracts.
- Sources/A0GenerativeUI owns the pinned A2UI SDK adapter, bounded reply validation, per-response surface lifecycle, action envelope generation and in-app producer instructions.
- App owns the active device-only Keychain session, foreground restoration, local display preferences and Settings, the native composer, profile-scoped sessions, Keychain credentials, saved-server/recovery UI, the VisionKit QR scanner, and foreground lifecycle.
- Tests owns synthetic protocol fixtures and security/recovery regressions.
- docs owns contract evidence and milestone acceptance.

## Local Contracts
- iOS 17+, Swift 6 concurrency; keep network work outside MainActor.
- HTTPS only, platform TLS validation, no automatic cross-origin redirects.
- Credentials and server response bodies never enter diagnostic logs or committed fixtures.
- Keep profiles, cookies, cursors, and callbacks isolated. Never auto-replay a mutating request.
- Preserve Agent Zero session authentication, CSRF and Origin checks.
- Computer status and explicit host tasks use optional `host_tasks_v1` through
  the existing server session. Older servers show presence only. Keep host
  permissions in Launcher, require a freshly reviewed per-chat target, persist
  host intent without generation tokens, and never replay or silently downgrade
  a host send to ordinary chat. See docs/HOST-COMPUTER.md.
- Chat-independent computer presence may display explicit Launcher permissions
  and host-ID-matched `host_setup_v1` results. It never supplies a task target or
  generation. Missing status means Not reported, not a failed verification.
- Persist a pending delivery before every mutating network call. Restore interrupted commands as uncertain; never replay them.
- Save profile metadata only after authentication succeeds. Password saving is opt-in, uses device-only when-unlocked Keychain items, and never stores secrets in profile files.
- New chat opens an explicit draft route; first-send context assignment must not dismiss it. Selecting an existing chat opens a stable-ID conversation route. State updates keep that route open; Back preserves drafts, and disconnect clears the route. Keep startup/profile loading on the persistent navigation container rather than the root list lifecycle.
- Render Markdown as native, non-executable blocks; no HTML execution or generic remote Markdown image loading. Validate HTTP(S) links and confirm the destination across expanded content, headings and collapsed previews.
- Subagent chat navigation uses only verified parent_context_id and subordinate-kind metadata between visible server contexts. Never infer relationships from titles, agent numbers or tool prose. Same-context activity remains separate. Unknown or false running is not completion. New-child badges baseline the first complete collection, survive same-session foreground refresh, stay authenticated-session/profile isolated, and never force navigation; child and parent selection preserve per-chat drafts and delivery receipts.
- Collapse long messages and routine activity. Group only consecutive known agent/tool/code_exe/util logs; warnings, errors, answers and unknown types stay separate. Keep stable group IDs while streaming. Pause following when reading or expanding; Latest resumes. An unmounted lazy footer is not evidence that the bottom is visible.
- Interpret icon:// markers only as presentation metadata. Map known names to SF Symbols and remove raw markers from headings; use a generic icon for unknown names. Tool summaries prefer structured kvps over bounded legacy JSON decoding. Keep raw event data behind explicit disclosure, preserve agent attribution, and never invent execution success.
- Browser screenshots load only from explicit tool capture metadata through the authenticated same-origin image_get endpoint; bound raster response and decode sizes, reject redirects, fence by profile/context/log epoch, and clear decoded images on background/disappearance. Historical image previews use bounded popovers. The approved live-viewer exception consolidates conversation captures in one expandable WebKit surface with native authenticated transport and acknowledged exclusive takeover; see docs/LIVE-VIEWER.md and docs/CHAT-MEDIA.md.
- Attachments are locally staged, bounded and profile-isolated; picking never uploads. Persist a delivery before multipart send or upload-plus-queue, preserve uncertain outcomes without replay, and do not let delayed picker/staging callbacks cross session/context identity. Separate protected file bytes from draft metadata to avoid rewriting binaries on keystrokes.
- The composer owns FocusState and an explicit keyboard-dismiss action; dismissing must not send or clear a draft. Settings display and send-mode preferences persist in UserDefaults, and use an isolated suite in UI tests. Authentication and credentials remain under existing session/Keychain ownership. Changing server confirms disconnection and retains drafts/uncertain receipts.
- Only explicit response a2ui fences or kvps.a2ui opt into generated UI. The approved native direct-media-preview exception recognizes bounded public HTTPS audio/video links in ordinary assistant prose, retains that prose, and reuses the trusted player; it does not convert arbitrary Markdown to A2UI. Exclude user/tool content, code, quoted examples, HTML and explicit/candidate protocol payloads; explicit surfaces take precedence. Discovery performs no network work, and media still requires explicit Load. Validate the entire bounded self-contained surface before SDK rendering; restrict to the documented local catalog with no functions or generic remote media. Never share a surface between chats/profiles/log epochs. A changed or invalid payload cancels action review; identical snapshots preserve local input. Generated actions require review, append to the draft, and use ordinary explicit Send with existing delivery protections. Never auto-send or treat an action as executed. In read-only activity views, disable draft-producing actions without disabling passive native media controls. Rich replies may append the exact capability contract to an explicitly submitted message, preserving IDs and showing it in an optional transcript disclosure; the preference applies to future sends. The user-authorized ImageCarousel loads public HTTPS raster images; AudioPlayer/Video explicitly load bounded public media files for local AVKit playback. These use separate credential-free clients with no redirects and DNS preflight. Audio/video playback stays inline in the reply with an explicit Unload action and a bounded video frame. Inline media, dictation and read-aloud share exclusive foreground audio ownership; handoff stops the prior activity, retains drafts, invalidates pending voice callbacks and never auto-resumes. Stopping an inactive card must not deactivate the current owner. Media never autoplays; local assets forbid external references and are released on background/disappearance/source change.
- Optional Jev is an explicit per-profile consent and device-only Keychain credential flow under Settings → Jev API key & rich replies. It is separate from Agent Zero provider credentials. Advertise candidates only on an explicit opted-in Send; persist a minimal attempt before the bounded direct TypeSafe POST. Never replay, transmit whole surfaces/history, accept invented provider content or cross profile/chat/epoch boundaries. Preserve prose on failure. See docs/GENERATIVE-UI.md.
- The launch cover reflects actual profile/session startup work, with no artificial delay or fabricated progress. The leading drawer must hide underlying content from accessibility while open, support close/escape/backdrop dismissal and restore focus to its opener; Reduce Motion suppresses sliding animation.
- Use the original Agent Zero assets and an adaptive neutral default palette; keep native Dynamic Type, 44-point actions and explicit contrasting foregrounds for prominent controls.
- Voice starts only from the explicit composer microphone action and inserts scoped cumulative snapshots directly into the existing draft without duplicating partial results or overwriting manual edits. Fence insertion by connection generation, ChatSession identity and context. Stop before Send/Clear and on background/interruption/disappearance/owner change; never auto-send. Continuous listening persists only as a local preference, default off, and never auto-starts. Require on-device recognition, keep raw audio transient, and review optional FoundationModels draft edits against the unchanged original. Hide routine saved-state copy while retaining accessible storage status and visible failure/retry. See docs/VOICE.md.
- Follow-up send mode defaults to Queue; route busy or already-queued chats through the server queue. Steer sends immediately through the ordinary message endpoint. Changing the preference never drains existing queued messages or replays uncertain deliveries; agent activity alone does not disable Send.
- The composer has one trailing Send/Stop control: empty drafts with running/paused/queued work show Stop; draft text or attachments show Send with an adjoining Stop menu. Preserve independent send/stop gating, 44-point targets and draft contents. Composer Stop clears the current chat queue before calling /api/stop, which cancels the server task tree. Attempt cancellation even if queue clearing fails; never retry either mutation, report partial/unknown outcomes and retain the receipt. Stop local voice, preserve drafts/attachments, and disable Send during the request. Only acknowledged success marks locally queued deliveries as removed; stale queue snapshots must not resurrect them. Other chats and detached external jobs are outside this control.
- Stop, Pause/Resume, Nudge and project mutations share profile-isolated ControlReceipts. Persist intent before submission and retain unknown outcomes; reads must not clear these receipts. Creating a chat in a project journals the create-plus-assign sequence, keeps its context ID available after partial failure, and never recreates or reassigns automatically. Test journals and authentication use synthetic namespaces.
- ProjectDocument stays in memory and preserves unknown/plugin fields and masked secrets on edits. Never archive or log project payloads, variables, MCP configuration or Git tokens. Clone accepts credential-free HTTPS repository URLs; its optional token is request-only. Clear sensitive editor state on background/account change. Delete requires the exact folder name and explains removal of the full server folder and chat assignments. See docs/PROJECTS.md.
- Provider choices use the server WebUI chat/embedding catalogs. Model suggestions use server-side model_search for the selected provider, slot type and API base, never direct provider credentials. Keep custom model IDs editable; cancel/fence stale suggestions and retain selections on read failure.
- Model preset selection from the composer changes only the current chat override; clearing returns to server-reported inheritance. Before a server context exists, keep the preset name in the profile-isolated draft archive and show it immediately. Explicit first Send journals create, preset application and message delivery; require preset acknowledgment before sending, retain failed choices and never replay uncertain mutations. Do not use the scoped-default select operation for this control. Global preset definitions are explicitly shared: validate Default, compare the editor baseline with a fresh collection before save/reset, journal the mutation and preserve unknown outcomes. Preserve sparse slots and opaque nested kwargs; strip only server-managed underscore/api_key fields at document and model-slot top level. Provider credentials and project-scoped defaults remain WebUI-owned. Clear transient editors on account/chat/background changes. See docs/MODEL_PRESETS.md.
- Context accounting must remain legible at accessibility sizes: use semantic ring text, stack category labels above fixed numeric groups, allow totals/units to reflow, and expand the popover without splitting digits.
- Context usage comes only from /api/plugins/_context_window/context_window. Keep the server prompt estimate separate from provider input/output/cache usage; never estimate missing categories from transcript length, invent a model window, or interpret missing usage as zero. Fence responses to the active generation and context.
- Legacy Speech authorization registration/completion must remain explicitly Sendable and nonisolated. Cross back to MainActor only through the awaited Boolean result, then recheck generation and lifecycle before microphone activation; retain background-queue grant/deny regressions.
- Keep the explicit Connect action reachable in the bottom safe area above the keyboard, with the same credential/busy gating as password-field submission.
- Selecting a saved profile does not connect. Backgrounding clears typed/loaded passwords even before connection. Identity edits clear loaded passwords; delayed callbacks must not cross identity changes. Removing a profile removes its saved credential first and retains local drafts/uncertain receipts.
- QR import accepts a plain ASCII HTTPS origin only. Review before applying, then require explicit login/Connect. Never import credentials, open a scanned link, look up Keychain, or persist during review. Stop camera access on dismissal/background and ignore stale/duplicate scan callbacks.
- Backgrounding suspends local transports and pending delivery work without clearing the connected route, reducer or generated replies. Foregrounding refreshes read-only state before Send is enabled. Relaunch restores only the last authenticated profile from a when-unlocked, device-only Keychain session cookie; revalidate the protected bootstrap and load profile-isolated drafts/receipts, then land the production cold launch on the new-chat draft with the sidebar closed. Do not erase older chat drafts or receipts; opening a draft is not a server create/send. Same-process background/foreground keeps the current route. Explicit disconnect removes the saved session. Never persist passwords without opt-in, replay commands, promise continuous background sockets, or save full transcripts/generated form input.
- Retry only foreground snapshot reads for allowlisted transient failures, with four jittered backoff attempts. Preserve the last display and drafts, disable Send until full current state returns, and offer explicit read-only retry after exhaustion. Never retry login, certificate/auth/CSRF failures, or mutations. Background/disconnect cancels recovery.
- While polling is healthy, retry realtime at 30/60/120-second intervals (120-second cap), refreshing the existing session without login. Stage socket state until handshake and full state match the current context/generation and collection versions. Polling remains authoritative until an atomic handoff; reject stale callbacks and cancel candidates on context changes, network recovery, background, or disconnect. A missing full socket state times out after 20 seconds.
- SessionRepository is the single writer per directory. Atomically save versioned archives, fail visibly on corruption or storage errors, and never store credentials or full transcripts.
- Separate archives by origin and username; retain them across disconnect, clear only the user-selected draft, and preserve unresolved delivery receipts.
- Synthetic fixture success is not live server or physical-device acceptance.
- Dependency installation, signing/distribution, commits and pushes require user authorization.
- The permanent app identity is com.terminallylazy.a0-ios, displayed as Agent Zero. project.yml owns marketing/build versions and generated Info.plist substitutions. Declare all four supported orientations for iPad multitasking. Keep privacy manifests and bundled third-party notices current. scripts/prepare-testflight.sh only archives locally; uploading and tester distribution are separate actions. Never commit signing identities, API keys, archives, raw test bundles or distribution logs. See docs/TESTFLIGHT.md.

- Plugins are separated by server-reported is_custom into Custom and Built-in, with Plugin Hub as the third collection. Artwork uses authenticated bounded reads only for the declared installed-plugin thumbnail path; public Hub images use the credential-free ImageDownloads client with its host/redirect/size policy. Downsample raster images off MainActor and clear thumbnail state on background/profile changes.
- Plugin card switches control global activation independently of detail navigation; always-active plugins stay locked on and unknown/pending state cannot trigger commands. Plugins use the existing core/installer APIs. Native install/update/delete/toggle/override commands use the shared ControlJournal and never replay. Keep capability restrictions, scoped inheritance and pending-command visibility; a refresh does not resolve an uncertain command.
- The user-authorized embedded-WebUI exception applies only inside PluginWebScreen, including Workspace canvas/rail surfaces: trusted server WebUI actions retain their own request/socket semantics and do not have native per-action receipts. This exception does not apply to native lifecycle controls. Use a nonpersistent WebKit store, validated secure HTTPOnly session cookie, exact-origin navigation checks, no credential-bearing URLs/scripts/bridge messages, and suppress the core WebUI fetchApi 403 retry. Plugin scripts are not a sandbox; never claim arbitrary custom transports or server effects are verified. Use the documented anti-phishing-page header only for the authenticated Dev Tunnels origin, load the authenticated /index.html document directly (the root splash replaces itself), verify the loaded shell before bootstrap, and show recovery on unexpected HTML/document replacement without replay. Clear web state on background/profile change/disconnect. The chat Markdown renderer remains non-executable. See docs/PLUGINS.md and docs/WORKSPACE.md.
- Workspace is entered through a single floating right-edge chat tab or the sidebar menu, without a duplicate top-toolbar icon. Keep the transcript centered; attach the transparent A0 tab flush to the edge, constrain vertical dragging above the composer, and hide it while the left drawer is open. Workspace opens the same authenticated shell and discovers tools through the original surface registry and extension hooks. Preserve native chat identity without creating a chat for a draft. Present registered icon tiles without a duplicate rail/tab row, and use full-width docked panel lifecycles on both phone and tablet so panel-only plugins work without a modalPath. Preserve canOpen restrictions and provide Back to tools; host layout changes apply only to the main document, never Browser/Desktop child frames.

- Match server theme is a local display preference, enabled by default. Read only the global selectable_theme activation/configuration and its fixed same-origin bounded CSS resource. Native UI receives validated semantic colors and gradients, never downloaded JavaScript or general CSS. Resolve CSS colors only in a credential-free network-disabled local document. Fence refreshes by connection generation and request identity; clear on background/disconnect/profile changes, opt-out, disabled/missing plugin or invalid data. Refresh on connection/foreground, after embedded screen dismissal/native theme lifecycle changes, and every 30 seconds while active. Keep light/dark selection local and preserve native accessibility, contrasting filled-control ink and platform-owned system sheets. See docs/THEMES.md.

## Work Guidance

- Native computer setup uses `host_setup_v1`, its own continuation journal and
  server-provided help. It never grants permissions, creates chats, replays
  mutations or clears host-control holds. See docs/COMPUTER-SETUP.md.
App Store screenshot fixtures stay DEBUG-only, use fictional local content and isolated persistence, and never delay production startup. The branded screenshot option renders the existing launch view directly; it is not evidence of an authenticated session.
Keep milestone slices bounded. Server changes and live-session mutations require
explicit task authorization.
Use explicit DTO coding keys and one reducer for poll and Socket.IO state.
