# Server theme matching

Settings → **Match server theme** defaults on. The app reads the connected server’s enabled Selectable Theme configuration and maps semantic colors into native chat, message/activity cards, composer, sidebar, Workspace edge tab, plugin cards/details, settings, and supporting controls. Native navigation bars, including the Agents inspector, use the panel color. Agents content and bottom safe areas use the same scoped theme as the conversation. The shared navigation styling also supplies the presentation background and extends the canvas under safe-area edges, preventing unthemed strips below forms. Plugin collection segments use input and primary colors with contrasting selection text; Plugin Hub filters, notices and other rows use the panel color. Its native search field uses input, text, border and muted tokens. Project/model forms and tools share themed list/form containers, and Settings uses the same scoped segmented control. Styling is per instance, never global UIAppearance. At accessibility text sizes, segmented choices become full-width stacked buttons so labels remain readable. Missing plugin artwork uses a contrasting themed placeholder. Light/Dark/System remains the local appearance choice; both plugin palettes are retained. Gradients render as SwiftUI linear gradients with the plugin’s angle and stop positions. Native system-owned interfaces retain their platform appearance.

## Ownership

`Sources/A0Core/ServerTheme.swift` owns read-only acquisition and bounded parsing. It requests `get_toggle_status` and `get_config` for `selectable_theme` with empty project/agent scopes, then reads only `/plugins/selectable_theme/webui/themes.css` from the authenticated origin. Built-in palettes come from that stylesheet rather than a separately maintained app copy. Custom palettes come from configuration. Unknown IDs use the plugin’s Aurora default when available; missing/disabled plugins, unexpected HTML, malformed palettes and unsupported color values fall back to the app’s neutral palette.

`App/NativeTheme.swift` owns transient refresh state, native semantic colors and gradient rendering. `ServerThemeHost` supplies the environment without changing conversation identity or rebuilding the navigation route. The local preference lives in DisplayPreferences; server palette data is not persisted. A generation mismatch prevents showing a previous profile’s palette immediately, even before a cancelled refresh finishes. Background/disconnect clears the palette. Reads refresh on connection/foreground, every 30 seconds while active, after embedded plugin screens close, after native Selectable Theme lifecycle commands, and through the explicit Refresh action. Changing the theme on another device therefore appears at the next active refresh. There is no background monitoring or theme mutation.

## Data boundary

Theme CSS is limited to 128 KiB, configuration to 256 KiB, custom themes to 100, color strings to 160 bytes and gradients to eight stops. Parsing extracts the declared semantic tokens from the plugin’s generated rules; it never injects the server stylesheet into native UI. Custom palettes must contain all 17 keys. Gradients accept the plugin’s degree angles, explicit percentage stops for built-ins, and evenly spaced custom stops. Arbitrary background images, layout rules, font downloads and remote CSS dependencies are unsupported.

A separate nonpersistent, credential-free WKWebView loads only a bundled blank document with `default-src 'none'`. Fixed local JavaScript uses CSS color validation and a one-pixel canvas to normalize hex/alpha, RGB, HSL, named and supported wide-gamut CSS colors to sRGB. Values pass as structured arguments, never executable strings. No server JavaScript, HTML, credentials or URLs enter this resolver. All output channels and counts are validated. Filled native controls choose black or white ink based on the tint’s luminance; Dynamic Type and VoiceOver remain native.

## Verification

`ServerThemeTests` covers current-server built-in palettes, custom colors/alpha, gradient stops, unknown-ID fallback, payload limits, disabled-plugin short-circuiting, authenticated read-only requests and redirect/interstitial rejection without retry. `PluginWebFixtureUITests.testNativeServerThemeSyncAndFallback` uses synthetic server palettes and actual native screenshots to check color matching, light/dark mode, local opt-out, custom gradients, refresh after embedded dismissal/foreground, and disabled/missing/invalid fallback. This fixture never reads owner theme settings or runs the live plugin. `testPluginHubThemeCoverage` verifies panel/input pixels and search filtering in both appearances; `testNativeThemeLightToolbarContrast` checks the light navigation icon against a 4.5:1 contrast floor. Plugin UI checks cover switches and accessibility-size selection, with project, model-preset and send-mode flows protecting shared controls. Exact run and device-install receipts belong in ACCEPTANCE.md.
